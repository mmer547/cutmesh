マニュアル

cutmesh は、水密な STL の内部に八分木ベースの多面体メッシュを作り、OpenFOAM の constant/polyMesh を直接書き出すメッシャーです。八分木のセルを STL で直接切断（カットセル）して壁面を作ります。 設定はすべて 1 つの JSON ファイル（meshDict.json）に書きます。

開発中のプロトタイプです。メッシュ品質は checkMesh と同じ式の自前チェックで確認していますが、OpenFOAM 本体での検証は限られています。 使う前に手元で checkMesh を実行してください。

インストール

必要なもの: Python 3.9 以上、numpy、scipy（断面図を描くなら matplotlib）。メッシュ生成に OpenFOAM は要りません。

git clone https://github.com/mmer547/cutmesh.git
cd cutmesh
pip install -e .                      # オフライン環境では --no-build-isolation（要 wheel）
python tools/build_rust.py            # 任意: Rust 拡張のビルド（約 4 倍速くなる）

インストールしない場合は、リポジトリの直下から python -m cutmesh で実行するか、PYTHONPATH にリポジトリのディレクトリを通してください。

使い方

cutmesh meshDict.json [-case DIR] [-noCheck]    # python -m cutmesh でも同じ
オプション意味
-case DIR出力先のケースディレクトリ（meshDict の case より優先）
-noCheck生成後の品質チェックを省く（大きなメッシュで約 1 割速くなる）

最小限の meshDict.json（STL の内部だけのメッシュ）:

{
  "domain": "model.stl",
  "baseCellSize": 0.01,
  "surfaceRefinement": { "default": 2 },
  "patchTypes": { "inlet": "patch", "outlet": "patch" },
  "case": "case"
}

case/constant/polyMesh が書き出され、続けて品質チェックの結果がログに出ます。パス（domain など）は meshDict.json のあるディレクトリからの相対パスです。STL の solid 名がそのままパッチ名になり、patchTypes に書かないパッチは wall になります。

ログの見方:

  • [ 63.15s] leak check (1.55s, peak 3.82 GB) — 各段階の終了時刻・所要時間・メモリのピーク
  • REPAIR: ... — 入力 STL を自動で直した内容（設定と入力の検査）
  • WARNING: ... — 直さずに見つけた問題（開いた辺、リーク、体積の不一致など）
  • 最後の checkMesh-style report — 非直交性・歪度・体積などの品質

攪拌槽の例題は examples/stirred_tank にあります。画像つきの説明は 実行例 を見てください。

cd examples/stirred_tank
python make_geometry.py               # サンプル STL を生成
cutmesh meshDict.json                 # → case/constant/polyMesh, case/constant/MRFProperties
python run.py                         # 断面図も欲しい場合 → slice_z.png, slice_y.png

meshDict.json

_ または // で始まるキーはコメントとして無視されます。知らないキーは警告されます（綴りの誤りで設定が黙って無視されないように）。

基本

キー意味既定値

baseCellSizeレベル 0 のセルの辺長 [m]。レベル L のセルは baseCellSize / 2^L必須

paddingSTL の外接箱の周りに足すベースセルの数1

細分化

キー意味既定値
surfaceRefinementsolid 名 → 細分化レベル。default で既定値{}
featureLevel特徴線（鋭角エッジ）の近くの細分化レベル（null = 表面の最大レベル）null
featureAngle特徴線を抽出する角度 [deg]30
refinementRegions体積の細分化領域 [{"cylinder": {...}, "level": n}][]
bufferLayersレベルの遷移ごとのバッファセルの数。1 にするとセル数が減る2
gapRefinement{"thickness": t, "level": L}: 流体の厚みが t 未満の所（スロットの先端、狭い流路）の壁を L まで細分化なし
autoGapRefinement{"cellsAcross": n, "maxLevel": L}（true で既定値）: 壁から法線方向に向かいの壁までの隙間の幅 w を測り、隙間に n 個のセルが入るレベル（上限 L）まで壁を細分化する。厚さを指定せずに、溝・スリット・狭い隙間がつぶれるのを防ぐn = 3、L = 表面レベルの最大 + 2

スナップと統合

キー意味既定値

featureSnapMax実験的: この距離まで特徴線へ寄せ、八分木セルが壊れる所だけ取り消す。一部のカットセルが反転するため既定では無効0.5
concaveSnapMax凹の鋭角エッジでは、固体側の節点をこの距離までエッジ上へ寄せる0.75
hangingSnap表面へ届かないぶら下がり節点の扱い（"free": 表面へ直接投影、"constrained": 動かさない）"free"
featureCaps凸の鋭角部でカット面を特徴線に沿わせる（"domain" / "zone" / "both" / false）"domain"
mergeRatio元の六面体の体積比でこれ未満のカットセルを隣のセルに統合する0.25

mergeWallFaces1 つのセルの、ほぼ同一平面の壁面の断片を 1 つの面にまとめるtrue

薄い形状

キー意味既定値

fillThinWalls中に固体の薄い壁があるのに角の頂点がどれも固体にないセルを分割する回数。壁が消えて両側の流体がつながるのを防ぐ（直交格子のみ）3

minRegionVolume流体の本体とつながっていない領域のうち、体積が全体のこの割合未満のものを削除する（それ以上は警告）1e-3

回転ゾーン（rotatingZones）

MRF やスライディングメッシュ（AMI）用の回転領域を円筒で指定します。円筒は八分木のカットで切断されるので、 円筒面そのものがメッシュの内部面になります（生成後にセル中心でゾーンを選ぶ方式ではありません）。 界面は粗いセルでも厳密に円筒面上にあるので、界面のために細分化する必要がありません。

"rotatingZones": [
  { "name": "rotor",
    "cylinder": { "point1": [0, 0, 0.06], "point2": [0, 0, 0.14], "radius": 0.07 },
    "surfaceLevel": 2, "volumeLevel": 2, "omega": 31.416, "nonRotatingPatches": [] }
]
キー意味
nameゾーン名（cellZone 名、faceZone は <name>_interface）
cylinder円筒: 軸の両端 point1・point2 と半径 radius
stl, origin, axis円筒の代わりに閉じた STL で与える（examples/stirred_tank/meshDict_stlRotor.json）
surfaceLevel / volumeLevelゾーンの面 / 内部の細分化レベル
omega角速度 [rad/s]（MRFProperties に書く）
nonRotatingPatchesゾーン内でも回転させないパッチ
wallProximity{"distance": d, "level": L}: ゾーンの面のうち STL から d 以内の部分だけを L まで細分化する。界面を壁すれすれに置く（狭い隙間の中に置く）場合に、ゾーン面全体を細かくせずに済む
amitrue にすると、界面をスライディングメッシュ用の 2 つのパッチに分け、dynamicMeshDict を書く（スライディングメッシュ）
conformingfalse にすると界面をメッシュに沿わせず、セル中心が円筒内にあるセルを cellZone にする（MRF 用。AMI には使えない）。界面が狭い隙間の中にあって沿わせられない場合に使う

出力: cellZones（回転領域）、faceZones（<name>_interface: 円筒界面、向きつき）、 constant/MRFProperties の雛形。複数のゾーンを置けます（重ならないこと）。

狭い隙間の中に界面を置く場合（ローター・ステーターなど）: 界面と両側の壁の間にそれぞれ 1 セル以上入るよう、 wallProximity の level を「隙間の半分 ≧ セル寸法」になるように選びます。隙間が狭いほどセル数が急に増えます （実行例: ローター・ステーター）。

スライディングメッシュ（AMI）

回転ゾーンに "ami": true を付けると、界面の内部面を、回転側のセルが持つ面と静止側のセルが持つ面の 2 つのパッチに分け、 界面の点を回転側だけ複製して切り離します（OpenFOAM の createBaffles と mergeOrSplitBaffles -split / splitBaffles をまとめて行うのと同じ）。 境界層は分ける前に付けます。あわせて constant/dynamicMeshDict（cellZone の剛体回転）を書きます。このゾーンは MRFProperties には書きません。

"rotatingZones": [
  { "name": "rotor",
    "cylinder": { "point1": [0, 0, 0.06], "point2": [0, 0, 0.14], "radius": 0.07 },
    "surfaceLevel": 2, "volumeLevel": 2, "omega": 31.416,
    "ami": true }
],
"openfoam": "com"

書き方は OpenFOAM の配布元によって違うので、openfoam で選びます。

openfoamパッチ（回転側 / 静止側）dynamicMeshDictOpenFOAM での手順
"com"（既定）<name>_AMI1 / <name>_AMI2、型 cyclicAMIdynamicMotionSolverFvMesh + solidBodyそのまま使える
"org10"・"org11"・"org12"<name>_nonCouple1 / <name>_nonCouple2、型 patchmover { type motionSolver; ... }createNonConformalCouples -overwrite <name>_nonCouple1 <name>_nonCouple2 でつなぐ
  • 界面は回転軸まわりの回転面である必要があります（円筒は常に可）。STL で与えたゾーンが回転面でない、または origin・axis がずれていると警告します。
  • "conforming": false のゾーンには使えません。複数のゾーンは、openfoam.com では multiSolidBodyMotionSolver、openfoam.org では motionSolverList で書きます。
  • 既存のメッシュは python -m cutmesh.ami で後から変換できます（コマンドとオプション）。

書き方は各配布元のチュートリアル（openfoam.com: interFoam/RAS/mixerVesselAMI、openfoam.org 10〜12: mixerVessel2D）に合わせていますが、 OpenFOAM 本体で読み込んで回すことはまだ確認していません。cutmesh の中では、回転側の点を実際に回してもセルが壊れず、界面が円筒の上に残ることを確かめています。

円筒ベースメッシュ（baseMesh）

回転機械向けに、八分木の根を直交格子の代わりに軸まわりの同心ブロックにできます。

"baseMesh": {
  "type": "cylindrical",
  "origin": [0, 0, 0], "axis": [0, 0, 1],
  "nz": 24,
  "core": { "halfWidth": 0.0375, "n": 6 },
  "blocks": [
    { "rOuter": 0.06, "nr": 2 },
    { "rOuter": 0.10, "nr": 3, "nTheta": 38 },
    { "rOuter": 0.155, "nr": 4 }
  ]
}
キー意味既定値
origin, axis回転軸（原点と方向）[0,0,0], [0,0,1]
zRange軸方向の範囲 [z0, z1]（origin からの距離）STL の範囲 ± baseCellSize
nz / dz軸方向の分割数 / 幅（全ブロック共通）dz = baseCellSize
core中心の正方形ブロック: 半幅 halfWidth、一辺の分割数 n必須
blocks外側へ並ぶ同心ブロック: 外半径 rOuter、半径方向の分割数 nr、周方向の分割数 nTheta必須
maxSizeRatioブロック境界をまたぐセル寸法の比の上限2.5
  • 最初のブロックは正方形から円へつなぐ O グリッドで、nTheta は 4 × core.n に固定。2 番目以降の nTheta は任意（隣のブロックの整数倍でなくてよい）。
  • ブロックの境界では両側の面を重ね合わせて共有の面に分けるので、分割数の比が任意でも適合した多面体メッシュになる（AMI 不要）。
  • 細分化のレベル L は目標寸法 baseCellSize / 2^L として扱う。各ブロックのセルが立方体に近くなるように分割数を選ぶ。
  • 最外ブロックの rOuter は STL の半径より大きくする（小さいと警告。STL は切り取られる）。

境界層（addLayers）

壁パッチにプリズム層を追加します。meshDict に書くと生成後に自動で追加され、既存のメッシュに後から追加することもできます （cutmesh 以外で作った polyMesh でも可）。

# meshDict.json に "addLayers": {...} を書く（例: examples/stirred_tank/meshDict_layers.json）
cutmesh examples/stirred_tank/meshDict_layers.json
# 既存のケースに追加
python -m cutmesh.layers CASE [layerDict.json] [-out CASE2] [-noCheck] [-ascii | -binary]
キー意味既定値
patches層を付けるパッチ名のリストtype が wall の全パッチ
nLayers層の数3
expansionRatio壁から内側への層厚の比1.2
finalLayerThickness最も内側の層の厚さ（relativeSizes なら局所セル寸法比）0.3
relativeSizes厚さを局所セル寸法に対する比で与えるtrue
minThickness総厚がこれ未満の所は層を付けない0.05
maxNonOrtho非直交角 [deg] がこれを超えるセルは不正とみなし、そこで層を薄くする65
maxSkewness歪度がこれを超える面のセルは不正とみなす（null で無効）4
maxGapFraction総厚を、向かい合う壁までの距離のこの割合以下に抑える（0 で無効）0.3
maxThicknessSlope壁に沿った総厚の変化の上限（層の端を徐々に細らせる）0.5

このほか minNormalCos, wallNonOrthMargin, cornerStretch, mergeWallPoints, concaveSlide, nRings, nSmooth, nIter, nCollapseIter があります（README の「境界層」）。 "addLayers": {} は既定値で層を追加します。狭い隙間がある形状では finalLayerThickness を 0.15 程度にすると、 目標の厚さに達する節点が大きく増えます。ログに、目標の厚さに達した壁節点・薄くなった節点・層なしの節点の割合が出ます。

書き出し形式（writeFormat）

polyMesh は既定でバイナリ（OpenFOAM の writeFormat binary と同じ形式）で書き出します。 大きなファイル（points・faces・owner・neighbour）がバイナリになり、 boundary・cellZones・faceZones は ASCII のままです。中身を目で確かめたいときや、 ASCII しか読めないツールに渡すときは "writeFormat": "ascii" にします。

約 69 万セルASCIIバイナリ
書き出し4.3〜4.5 秒0.14〜0.19 秒
ファイルの大きさ122 MB80 MB
読み込み（cutmesh）3.1 秒0.18 秒
  • ヘッダーは format binary;、arch "LSB;label=32;scalar=64";。faces は faceCompactList。
  • ラベルが 32 ビットに収まらないメッシュは label=64 で書く（64 ビットラベルでビルドした OpenFOAM が必要）。
  • python -m cutmesh.layers は入力と同じ形式で書く（-ascii / -binary で指定もできる）。

バイナリの形式は OpenFOAM のソースに合わせて書いていますが、OpenFOAM 本体で読めることはまだ確認していません。読めない場合は "writeFormat": "ascii" にするか、OpenFOAM の foamFormatConvert で変換してください。

高速化（Rust 拡張）

最近点・内外判定・符号付き距離、カット、面とセルの重心と体積、境界層の平滑化などを Rust（BVH + rayon による並列化）で計算します。 Rust ツールチェーン（cargo）があれば次でビルドされ、cutmesh/_core が置かれます。無ければ Python/NumPy の処理で動きます（結果は同じ）。

python tools/build_rust.py                          # cargo build --release + パッケージへコピー
CUTMESH_NO_RUST=1 python -m cutmesh meshDict.json   # Python の処理を強制（比較用）
例題PythonRust 拡張あり
examples/stirred_tank26 秒7 秒
別の実形状（55 万セル）162 秒41 秒
同、境界層の追加（3 層）51 秒27 秒

設定と入力の検査

メッシュを作り始める前に meshDict.json を検査します。

  • エラーで止める（見つかった問題をまとめて 1 つのエラーにする）: 必須キーがない、ファイルが見つからない、値の型・範囲が不正、 回転ゾーンの名前の重複・cylinder と stl の両方/どちらもなし、回転ゾーンどうしの重なり、JSON として読めない。
  • 警告（WARNING: meshDict:）: 知らないキー（近いキー名を示す）、surfaceRefinement などにある名前が STL の solid にない。
  • cutmesh コマンドはこれらのエラーをトレースバックなしで ERROR: ... と表示し、終了コード 1 を返します（引数の誤りは 2）。

入力 STL の自動修正: cutmesh が入力を直したときは、必ずログに REPAIR: で始まる行を出します。黙って直すことはしません。

修正理由
面積 0 の三角形を除く法線が決まらず、特徴線や交点の計算を乱す
重複した三角形は 1 枚だけ残す内外判定（光線の交差回数の偶奇）で交差が 2 回数えられ、内外が反転する
重なった逆向きの三角形の対（厚さ 0 の膜）は 2 枚とも除く同上
REPAIR: domain STL: removed 20 zero-area triangles, 50 duplicated triangles (one copy kept) (1350 -> 1280 triangles)

直さずに WARNING: を出すもの: 開いた辺、非多様体の辺、向きの食い違う辺。問題がなければ domain STL check: closed, consistently oriented, N triangles と出ます。メッシュの完成後には、メッシュの体積を STL の体積と比べます （volume check: mesh ..., STL ... (+x%)）。

コマンドとオプション

パスはリポジトリの直下から実行する場合のものです。pip install -e . をすれば cutmesh と python -m cutmesh.* はどこからでも使えます。

メッシュの生成: cutmesh

cutmesh meshDict.json [-case DIR] [-noCheck]      # python -m cutmesh でも同じ
オプション意味
-case DIR出力先のケースディレクトリ（meshDict の case より優先）
-noCheck生成後の品質チェックを省く
-h, --help使い方を表示する

終了コード: 0 = 成功、1 = 設定や STL のエラー（ERROR: ... と表示）、2 = 引数の誤り。

境界層の追加: python -m cutmesh.layers

python -m cutmesh.layers CASE [layerDict.json] [-out CASE2] [-noCheck] [-ascii | -binary]
引数・オプション意味
CASE層を付けるメッシュのケース（CASE/constant/polyMesh）
layerDict.json層の設定（境界層の表のキー）。meshDict を渡すと、その addLayers を使う。省略すると既定値

-noCheck品質チェックを省く

多数の STL をまとめて通し、判定（PASS / WARN / INVALID / ERROR）・セル数・品質・時間を一覧にします。1 ケースずつ別のプロセスで動くので、落ちても他のケースは続きます。

オプション意味
-j NN ケースを並列に走らせる（時間を比べるときは 1 にする）
--only PATTERNケース名で絞る（ワイルドカード可。複数回指定できる）
--cells-across N全ケースのベースセルを「外接箱の最長辺 / N」にする（既定 24）
--set KEY=JSON全ケースの meshDict のキーを上書きする（例: --set addLayers='{"nLayers": 3}'）

--no-images画像を描かない
--out DIR出力先（既定 benchmark/results/<スイート>-<日時>）

--save-baseline結果を benchmark/baselines/<スイート>.json に保存する
--timeout SEC1 ケースの時間の上限（既定 900 秒）
--vol-tol X体積の差がこの割合を超えたら WARN（既定 0.01）

既知の制約

  • STL は水密（閉じた・向きの揃った）である必要がある。開いた辺・自己交差は直さない（開いた辺は警告、自己交差は体積チェックの警告で分かることが多い）。
  • セルより薄い形状（薄翼・バッフル板）は、その厚さ程度まで細分化が必要。
  • 壁と別の壁が交わる入隅、円筒の縁、格子に沿わない凸の鋭角エッジは、セル寸法程度で面取りされることがある。
  • 歪度 > 4 の境界面が少数残ることがある（checkMesh では 1 項目の失敗になる可能性がある）。
  • メモリは 100 万セルあたり約 5 GB 使う。狭い隙間の中に回転ゾーンの界面を置くと、セル数とメモリが急に増える。
  • 幾何の問い合わせ以外（カット、セル統合、組み立て）の多くは Python のままで、時間の大半を占める。
