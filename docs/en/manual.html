Manual

cutmesh generates octree-based polyhedral meshes inside watertight STL geometry and writes OpenFOAM's constant/polyMesh directly. It cuts octree cells against the STL to create wall faces. All settings go into one JSON file, meshDict.json.

cutmesh is a prototype. Its built-in quality checks use the same formulas as checkMesh, and testing with OpenFOAM itself is limited. Run checkMesh locally before using a mesh.

Installation

Mesh generation requires Python 3.9 or later, NumPy, and SciPy. Use Matplotlib to plot cross-sections. OpenFOAM is optional.

git clone https://github.com/mmer547/cutmesh.git
cd cutmesh
pip install -e .                      # Offline: use --no-build-isolation (requires wheel)
python tools/build_rust.py            # Optional Rust build (about 100× faster on the stirred tank example)

To run from the source tree, use python -m cutmesh from the repository root or add the repository directory to PYTHONPATH.

Usage

cutmesh meshDict.json [-case DIR] [-noCheck]    # python -m cutmesh also works
OptionDescription
-case DIROutput case directory (overrides case in the meshDict)
-noCheckSkip the final quality check (about 10% faster on large meshes)

A minimal meshDict.json for meshing the inside of an STL follows.

{
  "domain": "model.stl",
  "baseCellSize": 0.01,
  "surfaceRefinement": { "default": 2 },
  "patchTypes": { "inlet": "patch", "outlet": "patch" },
  "case": "case"
}

cutmesh writes case/constant/polyMesh and then logs the quality check results. Paths such as domain are relative to the directory containing meshDict.json. STL solid names become patch names. Patches omitted from patchTypes default to wall.

The log contains these messages.

  • [ 63.15s] leak check (1.55s, peak 3.82 GB) shows when each stage finished, its duration, and peak memory.
  • REPAIR: ... describes automatic STL repairs. See Configuration and input checks.
  • WARNING: ... reports problems such as open edges, leaks, or volume mismatches.
  • The final checkMesh-style report summarizes non-orthogonality, skewness, volume, and other quality metrics.

The stirred tank case is in examples/stirred_tank. See Examples for the walkthrough and images.

cd examples/stirred_tank
python make_geometry.py               # Generate the sample STL
cutmesh meshDict.json                 # → case/constant/polyMesh, case/constant/MRFProperties
python run.py                         # Also plot cross-sections → slice_z.png, slice_y.png

Rotating zones (rotatingZones)

Define rotating regions for MRF or sliding meshes (AMI) with cylinders. cutmesh cuts the octree against the cylinder during meshing, so the cylinder surface itself becomes internal mesh faces. The interface lies on the cylinder even in coarse cells, so it does not require extra refinement.

"rotatingZones": [
  { "name": "rotor",
    "cylinder": { "point1": [0, 0, 0.06], "point2": [0, 0, 0.14], "radius": 0.07 },
    "surfaceLevel": 2, "volumeLevel": 2, "omega": 31.416, "nonRotatingPatches": [] }
]
KeyDescription
nameZone name (cellZone name, with <name>_interface as the faceZone name)
cylinderCylinder defined by axis endpoints point1 and point2 and a radius
stl, origin, axisUse a closed STL to define the zone (see examples/stirred_tank/meshDict_stlRotor.json).
surfaceLevel / volumeLevelRefinement levels on the zone surface and inside the zone
omegaAngular velocity [rad/s] written to MRFProperties
nonRotatingPatchesPatches that stay stationary inside the zone
wallProximityWith {"distance": d, "level": L}, refine the zone surface to L only within d of the STL. Use this to keep refinement local when the interface lies near a wall or in a narrow gap.
amiSet to true to split the interface into two sliding-mesh patches and write dynamicMeshDict.
conformingSet to false to include cells in the cellZone by their centers without cutting the interface. Works with MRF only. Use it when a narrow gap prevents a conforming interface.

cutmesh writes cellZones for the rotating regions, faceZones for the oriented cylinder interfaces (<name>_interface), and a constant/MRFProperties template. Multiple zones are supported if they do not overlap.

For an interface in a narrow gap, such as between rotor and stator, fit at least 1 cell between the interface and each wall. Choose the wallProximity level so the cell size is at most half the gap width. The cell count rises sharply as the gap narrows. See the rotor–stator example.

Sliding meshes (AMI)

Set "ami": true on a rotating zone to split its internal interface faces into two patches, one owned by rotating cells and one by stationary cells. cutmesh duplicates the interface points on the rotating side to separate the patches. This combines the effects of OpenFOAM's createBaffles and mergeOrSplitBaffles -split / splitBaffles. cutmesh adds any boundary layers before splitting, then writes constant/dynamicMeshDict for rigid-body rotation of the cellZone. AMI zones are omitted from MRFProperties.

"rotatingZones": [
  { "name": "rotor",
    "cylinder": { "point1": [0, 0, 0.06], "point2": [0, 0, 0.14], "radius": 0.07 },
    "surfaceLevel": 2, "volumeLevel": 2, "omega": 31.416,
    "ami": true }
],
"openfoam": "com"

Use openfoam to select the output dialect for your OpenFOAM distribution.

openfoamPatches (rotating / stationary)dynamicMeshDictOpenFOAM step
"com" (default)<name>_AMI1 / <name>_AMI2, type cyclicAMIdynamicMotionSolverFvMesh + solidBodyUse directly
"org10", "org11", "org12"<name>_nonCouple1 / <name>_nonCouple2, type patchmover { type motionSolver; ... }Couple them with createNonConformalCouples -overwrite <name>_nonCouple1 <name>_nonCouple2
  • The interface must be a surface of revolution about the rotation axis. Cylinders satisfy this requirement. cutmesh warns if a zone STL is not a surface of revolution or if origin or axis is misaligned.
  • AMI requires conforming zones. For multiple zones, cutmesh writes multiSolidBodyMotionSolver for openfoam.com and motionSolverList for openfoam.org.
  • Use python -m cutmesh.ami to convert an existing mesh.
  • Cut cells outside the top and bottom cylinder rims can wrap around them, leaving bent interface faces. OpenFOAM represents each face using its center, effectively chamfering the rim so the two sides stop matching as they rotate. amiExactRims (default true) inserts rim points on crossing edges and splits outer cells in two along one plane of the bent face, so the interface follows the rim exactly. cutmesh leaves any splits that would create poor-quality cells in place and reports their count. The standalone python -m cutmesh.ami conversion has no zone geometry for this step.

The output follows the distribution tutorials, interFoam/RAS/mixerVesselAMI for openfoam.com and mixerVessel2D for openfoam.org 10–12. The case in examples/stirred_tank/meshDict_ami.json (about 100,000 cells with 90° of laminar rotation) completed in openfoam.com v2606 pimpleFoam and OpenFOAM-13 foamRun using the "org12" dialect. In OpenFOAM-12, both this mesh and a rimless cylindrical zone halted with a floating-point exception in cyclicFvPatch::makeWeights when rotation began. The same mesh runs in OpenFOAM-13, which points to an OpenFOAM-12 issue.

Cylindrical base mesh (baseMesh)

For rotating machinery, use concentric blocks around the rotation axis as the octree roots. cutmesh lays out the central square, ring radii, and divisions automatically. A minimal configuration follows.

"baseMesh": { "type": "cylindrical", "origin": [0, 0, 0], "axis": [0, 0, 1] }
KeyDescriptionDefault
origin, axisRotation axis (origin and direction)[0,0,0], [0,0,1]
zRangeAxial range [z0, z1] measured from originSTL extent ± baseCellSize
nz / dzNumber or width of axial divisions (shared by all blocks)dz = baseCellSize
rOuterOuter radius of the outermost block in the automatic layoutSTL radius + 2/3 × cellSize
cellSizeTarget radial and circumferential cell width for the automatic layoutSmaller of baseCellSize and dz
core, blocksFor manual block layout, supply both keys. Otherwise omit both.Automatic layout
maxSizeRatioMaximum cell size ratio across block boundaries2.5

Automatic layout (omit core and blocks)

  • A small 2×2 central square has a half-width of 0.5–0.95 times cellSize. An O-grid ring with 8 circumferential divisions connects it to a circle of twice that radius. Beyond this, concentric rings grow by about 1.5625× in radius until rOuter.
  • Each ring's nTheta is a multiple of 4 chosen to make the circumferential width near mid-ring close to cellSize. The radial width is at most 1.15 × cellSize. Every edge is at most 1.3 times baseCellSize, avoiding extra refinement levels.
  • Only the 4 central cells and those in the first ring lack circumferential alignment. When a solid shaft or hub lies on the axis, most of these cells fall inside it.
  • cutmesh finds the radii of coaxial cylinders in the domain and zone STLs (such as shafts, hubs, tank walls, and blade-tip circles) and coaxial rotating or refinement cylinders. It positions radial vertices so each surface falls 1/3 of the way through a cell. When refinement halves the cell, the surface remains at 1/3 or 2/3 of the new cell, avoiding thin cut cells. The central square is sized to keep a similar separation between the inner cylinder (shaft) and the midpoint of its edge.
  • The log shows the layout and detected radii. Its "core": ..., "blocks": [...] entries can be reused for manual layout. Blocks with nonuniform spacing have nr + 1 radial vertices in radii.

Manual layout

"core": { "halfWidth": 0.0375, "n": 6 },
"blocks": [
  { "rOuter": 0.06, "nr": 2 },
  { "rOuter": 0.10, "nr": 3, "nTheta": 38 },
  { "rOuter": 0.155, "nr": 4 }
]
  • core is the central square block with half-width halfWidth and n divisions per side. blocks lists the concentric blocks outward, with outer radius rOuter, radial divisions nr, and circumferential divisions nTheta.
  • The first block is an O-grid connecting the square to a circle, so nTheta is fixed at 4 × core.n. Later blocks can use any nTheta, even when adjacent counts are not integer multiples. Optional radii sets the nr + 1 radial vertices.
  • Set the outermost rOuter greater than the STL radius. A smaller value triggers a warning and clips the STL.

Both layouts

  • At block boundaries, cutmesh overlays faces from both sides and splits them into shared faces. This produces a conforming polyhedral mesh for arbitrary division ratios, without AMI.
  • Refinement level L represents a target size of baseCellSize / 2^L. Refinement halves all 3 dimensions together, so base cells narrower than the axial width dz can become too fine in cross-section. When laying out blocks by hand, choose divisions that give near-cubic cells, as the automatic layout does.

Boundary layers (addLayers)

cutmesh adds prismatic layers to wall patches. Set addLayers in the meshDict to add layers after meshing, or run the standalone command on an existing mesh. The command also supports polyMesh files created with other tools.

# Add "addLayers": {...} to meshDict.json (see examples/stirred_tank/meshDict_layers.json)
cutmesh examples/stirred_tank/meshDict_layers.json
# Add layers to an existing case
python -m cutmesh.layers CASE [layerDict.json] [-out CASE2] [-noCheck] [-ascii | -binary]
KeyDescriptionDefault
patchesList of patches to receive layersAll patches of type wall
nLayersNumber of layers3
expansionRatioRatio of successive layer thicknesses away from the wall1.2
finalLayerThicknessThickness of the innermost layer, as a fraction of the local cell size if relativeSizes is enabled0.3
relativeSizesSpecify thickness as a fraction of the local cell size.true
minThicknessOmit layers below this total thickness.0.05
maxNonOrthoTreat cells above this non-orthogonality angle [deg] as invalid and reduce the layer thickness there.65
maxSkewnessTreat cells adjacent to faces above this skewness limit as invalid. null disables the check.4
maxGapFractionLimit total thickness to this fraction of the distance to the opposing wall. Set to 0 to disable.0.3
maxThicknessSlopeLimit changes in total thickness along the wall so the layers taper gradually.0.5

Additional settings include minNormalCos, wallNonOrthMargin, cornerStretch, mergeWallPoints, concaveSlide, nRings, nSmooth, nIter, and nCollapseIter. See Boundary layers in the README. Use "addLayers": {} to add layers with the defaults. For narrow gaps, a finalLayerThickness of about 0.15 lets many more vertices reach the target thickness. The log reports the percentages of wall vertices at the target thickness, with thinner layers, and without layers.

Export format (writeFormat)

cutmesh writes polyMesh in binary by default, using the OpenFOAM writeFormat binary format. The large points, faces, owner, and neighbour files are binary. The boundary, cellZones, and faceZones files are ASCII. Set "writeFormat": "ascii" to inspect the files by hand or use them with ASCII-only tools.

About 690,000 cellsASCIIBinary
Write4.3–4.5 s0.14–0.19 s
File size122 MB80 MB
Read (cutmesh)3.1 s0.18 s
  • The header specifies format binary; and arch "LSB;label=32;scalar=64";. The faces file is a faceCompactList.
  • Meshes whose labels exceed 32 bits use label=64 and require an OpenFOAM build with 64-bit labels.
  • python -m cutmesh.layers writes the input format by default. Override it with -ascii or -binary.

The binary format follows the OpenFOAM source. Reading it with OpenFOAM itself has yet to be verified. If reading fails, set "writeFormat": "ascii" or convert using OpenFOAM's foamFormatConvert.

Rust acceleration

The Rust extension covers nearly every meshing stage: geometry queries (nearest points, inside/outside tests, and signed distances), octree refinement and balancing, vertex snapping, STL and rotating-zone cuts, merging, assembly, leak and quality checks, and boundary-layer smoothing. It uses BVH acceleration and Rayon for parallelism. With the Rust toolchain (cargo) installed, the build below installs cutmesh/_core. The Python/NumPy fallback produces the same result.

python tools/build_rust.py                          # Run cargo build --release and copy into the package
CUTMESH_NO_RUST=1 python -m cutmesh meshDict.json   # Force the Python path for comparison

Configuration and input checks

cutmesh validates meshDict.json before meshing.

  • Errors stop meshing. One message collects missing required keys or files, invalid types or ranges, duplicate zone names, zones with both or neither of cylinder and stl, overlapping zones, and invalid JSON.
  • Warnings (WARNING: meshDict:) report unknown keys with suggestions and names in settings such as surfaceRefinement that do not match an STL solid.
  • The cutmesh command prints ERROR: ... without a traceback and returns exit code 1. Invalid command-line arguments return 2.

Automatic STL repairs always produce a log line beginning with REPAIR:.

RepairReason
Remove zero-area triangles.Their normals are undefined, which disrupts feature-edge and intersection calculations.
Keep one copy of each duplicate triangle.Ray parity tests count duplicate intersections twice, reversing the inside/outside result.
Remove both triangles in each coincident pair with opposite orientations (a zero-thickness membrane).Same as above.
REPAIR: domain STL: removed 20 zero-area triangles, 50 duplicated triangles (one copy kept) (1350 -> 1280 triangles)

Open edges, non-manifold edges, and inconsistent orientations produce WARNING: messages and require repair in the source STL. For a valid STL, the log reads domain STL check: closed, consistently oriented, N triangles. After meshing, cutmesh compares the mesh volume with the STL volume （volume check: mesh ..., STL ... (+x%)）。

Known limitations

  • The STL must be watertight, closed, and consistently oriented. Open edges and self-intersections require repair in the source geometry. Open edges generate warnings and self-intersections often show up in the volume check.
  • Geometry thinner than a cell, such as thin blades or baffles, needs refinement to around its thickness.
  • Re-entrant wall corners and cylinder rims can be chamfered at cell scale. Exact cuts capture sharp convex edges, while chamfering can persist at concave edges or where curved surfaces meet.
  • A few boundary faces can have skewness > 4, which can cause a checkMesh quality check to fail.
  • Memory use is about 1.5–2 GB per million cells. Placing a rotating-zone interface in a narrow gap can sharply increase both cell count and memory use.
  • The Python/NumPy fallback is substantially slower than the Rust extension, by about 100× in the stirred tank example.
