## 決まりごと

- **cutmesh が入力を自動で修正したときは、必ずログに `REPAIR:` の行を出す**（何を何件直したか）。黙って直さない。
  直さずに見つけた問題は `WARNING:` の行にする。ベンチマークは `REPAIR:` の行を結果の notes 欄に
  `repaired: ...` として載せる。
- 修正するたびに、下の「修正履歴」に内容とベンチマークの前後を記録する。

## 優先度 P0: 入力の堅牢化（小さな変更で、きれいな入力の結果は変わらない）

### 1. 重複した三角形を読み込み時に取り除く — **済（2026-11-13、下記「修正履歴」）**
- **原因**: `Surface.inside()` は +x 方向の光線 1 本の交差回数の偶奇で内外を決める
  （`geometry.py:440`、Rust 側も同じ）。同じ三角形が 2 枚あると、そこを通る光線だけ交差が 2 回
  数えられ、内外が反転する。突起が +x 方向にだけ伸びるのは、このためと考えられる。
  重複だけの STL で再現し、潰れた三角形だけなら PASS することを確認済み。
- **対処**: `Surface.__init__` で、頂点を溶接したうえで次のように処理し、件数をログに出す。Rust の `TriMesh` には処理後の三角形を渡す。
  - 同じ向きの重複は 1 枚だけ残す。
  - 逆向きの重複（厚さ 0 の内部の膜）は 2 枚とも除く。
  - 面積 0 の三角形は除く。
- **完了条件**: dirty_duplicates が PASS になる。他のケースのセル数は変わらない（`--baseline` で確認）。

### 2. 入力 STL の検査をメッシャー本体に入れる — **済（2026-11-13、下記「修正履歴」）**
- `benchmark/stl_check.py` の処理（開いた辺、非多様体の辺、向きの不一致）を `cutmesh/geometry.py` に移す。
  読み込み直後に件数と代表的な場所をログに出し、開いた辺があれば `WARNING` にする。
  `"strictInput": true` のときはエラーで止める。
- **体積のチェック**: 完成したメッシュの体積を STL の符号付き体積と比べ、5% 以上ずれていたら警告する
  （「STL が開いているか、自己交差している可能性」）。どちらも既に計算している値なので、ほぼ無料。
  dirty_overlap（−40%）と、開いた STL の取り違えを捕まえられる。
- **完了条件**: dirty_open_box が読み込みの時点で WARNING になり、`strictInput` なら ERROR で止まる。
  bunny（開いた辺 15）は警告付きでこれまでどおりメッシュになる。

### 3.（任意）内外判定を多数決にする
- 3 方向の光線の多数決にすると、小さな穴（bunny の開いた辺 15 本）や、残った重複に強くなる。
  内外判定の回数は 3 倍になるので、所要時間を測ってから既定にするか決める。
  さらに強くするなら一般化巻き数（winding number）を使う方法もあるが、Rust 側の作業が大きい。

## 優先度 P1: メッシュの品質

### 4. 薄い壁と外壁の接合部のリーク
- **見当（要確認）**: `_thin_wall_cells`（`mesher.py:778`）は「角の頂点がどれも固体に入っていない」セルだけを
  対象にしている。壁と天井の接合部のセルは、天井側の角が固体に入るので対象から外れ、細分化されない。
  README の既知の制約「壁と別の壁が交わる入隅では面取りが残る」の、一番悪い形がリークとして出ている。
- **対処**（案を 2 つ併用）:
  1. 判定を緩める: 角の一部が固体に入っていても、セル内の線上に「入って出る」対があり、
     その間の固体がセルの角の固体とつながっていなければ対象にする。
  2. リーク検査の結果を細分化に戻す: `checkLeaks` が見つけた場所のセルを分割して作り直す
     （最大 2 回）。原因が何であってもリークを塞げる、安全網として。
- **完了条件**: thin_walls のリーク 0。セル数と時間の増え方を記録する（今は 27 万セル・59 秒）。

### 5. 格子に沿わない凸エッジのギザギザ（2026-11-13 に原因を調査、本命 A を任意機能として実装）

**計測**（`tools/edge_check.py` と同じ方法: 特徴線上の点から、最も近いメッシュの境界辺までの距離 / hmin）

| 設定 | cube_rotated: 平均 / p95 / 0.2 hmin 超 | cone_tip: 平均 / p95 / 0.2 hmin 超 | 品質 |
|---|---|---|---|
| 既定（featureSnapMax 0.5） | 0.082 / 0.40 / 16.5% | 0.096 / 0.44 / 19.3% | cube: 歪度 > 4 が 3 面 |
| featureSnapMax 0.75 | 0.058 / 0.35 / **10.4%** | 0.072 / 0.43 / **12.7%** | cube: 歪度 > 4 が 2 面。スイート全体でも判定の悪化なし |
| featureSnapMax 1.0 | 0.078 / 0.40 / 15.3% | 0.090 / 0.44 / 17.6% | 取り消しが増えて逆効果 |
| featureLevel 3（特徴線だけ 1 段細かく） | 0.074 / 0.39 / 14.2% | 0.082 / 0.39 / 15.6% | ずれは hmin に比例して残る（直らない） |

- cone_tip の縁は格子面（z = 0）にちょうど乗っているが、これは原因ではなかった。円錐を 0.3° 傾けて
  格子面から外すと、むしろ 27% に悪化する。
- 欠けている点の近くのカット面で、`featureCaps` の hook がどう判断したかを数えた（実験用のスクリプトで hook を差し替えて記録）:
  - cube_rotated:
    - 37%: 特徴線の点がカット面の外にある（扇形の分割を断念）
    - 31%: 特徴線が遠いと判定（何もしない）
    - 23%: 1 点だけ足して扇形に分割したが、両端は直線のまま
    - 「特徴線に沿って分割」はわずか 1%
  - cone_tip: 65% が「特徴線の点がカット面の外」、残りは近くにカット面自体がない。

**原因（2026-11-13 に調べ直した結果。最初の見当は誤り）**

- **最初の見当（誤り）**: 「流体のくさびがセルの頂点の間から突き出していて、レベルセットに見えない」と考えた。
  欠けている点を含む最小セルの頂点を調べると、流体側の頂点がない（= くさびが頂点の間にある）のは
  cube_rotated で 9%、cone_tip で 0% だけ。7〜9 割は、流体側の頂点が 2 個以上ある普通のカットセルだった。
  面の単位で見ても、特徴線が貫く面の 4 頂点がすべて固体側なのは 16%（きれいに取れている所でも 21%）で、差がない。
- **実際の原因**: 特徴線上の頂点の間隔が空いている区間で欠けている。
  - 欠けている点で、最も近い特徴線上の頂点が 0.5h より遠いのは、cube_rotated で 68%、cone_tip で 52%。
    きれいに取れている点では 11% と 4% だけ。
  - 特徴線上の頂点は平均して約 1h に 1 個ある（cube_rotated は 775 個 / 長さ 730h）が、並びが偏っていて、空白の区間ができる。
  - 特徴線上の頂点は、次の 2 つでしかできない。
    1. スナップ: 0.5h 以内に格子の頂点がある所だけ。
    2. chord hook: 面の切断線を貫通点で折り曲げるときに挿し込む点。
  - chord hook は、レベルセットで切られる面にしか呼ばれない。ところが、スナップで頂点が表面上（値 0）に
    移されると、面の符号が `0P00` や `00N0` になる。こうなった面は丸ごと固体または流体として扱われ、切られないので、貫通点が入らない。
    実際に欠けている箇所のセルでは、6 面のうち 4 面がこうなっていた。
  - 空白の区間では、カット面の輪郭に特徴線上の点が 2 つ揃わず、特徴線に沿った分割ができない。
    重心に最も近い 1 点での扇形の分割に頼ることになり、それも断念するか、両端が面取りになる。

**改良案（調べ直した後）**
1. **計測をベンチマークに入れる**（先にやる）: 特徴線からのずれ（平均・p95・0.2 hmin 超の割合）と、
   特徴線上の頂点の間隔（最大・0.5h 超の区間の割合）を `run_bench.py` の指標にする。
   さらに、ずれが最も大きい 3 か所の拡大図をケースのフォルダに出す。
2. **即効策: `featureSnapMax` の既定を 0.5 → 0.75 にする**。0.2 hmin を超える点が約 4 割減り、スイート全体でも判定の悪化はない。
   ただし tet 分解の負の数は増える（cube 89 → 128）。1.0 では取り消しが増えて逆効果。
3. **本命 A: 空白の区間に絞ってスナップする**（今の仕組みの中でできる）。
   - スナップのあと、特徴線ごとに頂点の間隔を調べる。間隔が約 1h を超える区間ごとに、その区間の中ほどに最も近い頂点を 1 つ選び、特徴線の上へ移す。
   - 選ぶ範囲は `featureSnapMax` までとし、既存の「セルが壊れたら取り消す」検査をそのまま使う。
   - `featureSnapMax` を全体で上げると関係のない頂点まで動いて取り消しが増えるが（1.0 で逆効果だった理由）、
     必要な所だけ動かすので、その副作用が小さい。
4. **本命 B: 特徴線を面に埋め込む**（大きい）。
   - 面がレベルセットで切られるかどうかにかかわらず、特徴線が貫く面には貫通点を頂点として入れる。
     面ごとに決めて両隣のセルで共有するので、整合は保たれる。
   - そのうえで、面とカット面を特徴線に沿って分割する。
   - A で空白が残る所（セルが壊れるので動かせない所）にも効くが、カットの核（Python と Rust）の変更が大きい。
5. **（取り下げ）両側の STL 平面による半平面クリップ**: くさびが頂点の間にある場合の対策だが、そのケースは少数だったので効果は小さい。

4. 効かないもの: 特徴線だけの細分化（ずれが hmin に比例して残る）、格子面との一致の回避。

### 2026-11-13 — PR #26 のレビュー指摘（Codex、P2 × 2）への対応

**1. 重複三角形の除去が二乗の時間になる**（`cutmesh/geometry.py` `repair_triangles`）
- 重複のグループごとに配列全体を走査していた。グループごとの向きの数を `bincount` で一度に数え、残す 1 枚を `np.unique` で一度に選ぶ形に変えた（ループなし）。
- 結果は旧実装と同じ: ランダムな 200 入力で、残る三角形・領域・件数がすべて一致した。テストも 1 件追加（同じ面の 3 枚 + 逆向き 1 枚など）。
- 表面全体を 2 重にした STL での時間:

| 三角形の数 | 前 | 後 |
|---|---|---|
| 20,480 | 0.71 秒 | 0.21 秒 |
| 81,920 | 8.34 秒 | 0.92 秒 |
| 327,680 | （推定 2 分以上） | 4.50 秒 |

**2. 入力の診断に失敗すると、ベンチマーク全体が止まる**（`benchmark/run_bench.py`）
- 空や壊れた STL では `check_file()` が失敗し、そのあと `inp["bbox"]` で KeyError になってスイート全体が止まり、報告も書かれなかった。
- 診断に失敗したケースは、その場で ERROR（`input diagnostics failed: ...`）として記録して次へ進むようにした。
- さらに、1 ケースで想定外の例外が出ても、スイート全体は止めずにそのケースを ERROR にする。
- 確認: 空の STL、中身のない ASCII STL、立方体を並べたスイートで、前の 2 つが ERROR、立方体が PASS、報告も出力された。

**ベンチマーク**: synthetic・local とも、基準との差なし（判定・セル数とも同じ）。テスト 65 件通過。

**未対応（別件）**: cutmesh 本体も、空の STL を読むと分かりにくい `struct.error` を出す。

### 2026-11-13 — 計画 5 の本命 A: 凸エッジ上の節点の空白を埋めるスナップ（`featureGapSnap`、既定は無効）

**変更内容**
- `cutmesh/mesher.py`: `fill_feature_gaps()` を追加。通常の特徴線スナップのあとに動く。
  - 凸の特徴線に沿って、特徴線上の節点から 0.5 セルより離れた区間を探す。
  - 区間ごとに、エッジ上の行き先がその区間に入り、移動距離が最も短い節点を 1 つ選び、エッジの上へ移す（`featureGapSnap` × セル寸法まで）。
  - 0.5 セルより遠くへのスナップ（far snap）として扱うので、八分木セルが壊れる所は既存の検査で取り消される。凹エッジは対象外（専用のスナップがある）。
  - ログには `feature gaps: N stretches ...: M got a vertex snapped onto the edge, K have no vertex within R cell` と出る。
- 設定キー `featureGapSnap`（既定 0 = 無効）を追加し、README に記載した。
- `tests/test_feature_gaps.py` を追加（3 件: 既定では動かない、有効にするとエッジから離れた部分が 6 割未満になる、メッシュが壊れずログが出る）。全 68 件通過。
- `benchmark/run_bench.py`: 特徴線の取れ具合（`edge > 0.2 hmin`）を指標に追加した。基準との差が 2 ポイントを超えると `edges` の行で知らせる。
- `benchmark/suites/synthetic.json`: `cube_rotated_gapsnap`・`cone_tip_gapsnap`・`star_prism_gapsnap` を追加した（`featureGapSnap` 0.75）。

**結果**（特徴線上の点のうち、メッシュの辺から 0.2 最小セル以上離れた割合）

| ケース | 無効 | 有効（0.75） |
|---|---|---|
| cube_rotated | 16.5%（歪度 > 4 が 3 面で WARN） | **5.1%**（歪度 > 4 は 0、PASS） |
| cone_tip | 19.3% | **8.1%** |
| star_prism | 7.7% | 6.5% |

**既定を無効にした理由**: 境界層を付けると、このエッジ（2 つの壁の層がぶつかる入隅）で層が薄くなる。
- 全厚で層が付く壁の点の割合: サイクロン 94.2% → 89.4%、攪拌槽 97.6% → 97.0%（歪度・負の体積・非直交性は悪化なし）。
- 半径 4.4 セルの円筒での境界層のテスト 2 件（`test_concave_layers`）が失敗する。
- 次の 3 つも試したが、「角がよく取れるほど層が薄くなる」関係は変わらなかった。
  - 固体側の節点だけを動かす
  - 届く範囲を 0.6 に縮める
  - 既存の節点から 0.3 セル離す、セルの最後の流体側の節点は動かさない

  埋める基準を厳しくする（0.35 / 0.25 セル）と、取り消しが増えて逆に悪化した。

**残り**
- cone_tip の底の縁（格子面に乗っている）に目に見えるギザギザが残る。届く範囲内に動かせる節点がない区間で、本命 B（特徴線を面に埋め込む）が必要。
- 既定で有効にするには、入隅の境界層の処理（`layers.py` の concaveSlide など）が、エッジ上へ寄せた節点の周りでも層の厚さを保てるようにする必要がある。
- ベンチマークの既存ケースは判定・セル数とも変化なし（既定が無効のため）。基準は `baselines/*.json` を更新済み。
