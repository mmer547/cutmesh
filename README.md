# cutmesh — OpenFOAM 用の八分木カットセル・メッシャー

水密な STL の**内部**に八分木ベースの多面体メッシュを生成し、OpenFOAM の `constant/polyMesh` を
直接書き出すメッシャーです（開発中のプロトタイプ）。八分木のセルを STL で直接切断（カットセル）して
壁面を作ります。

## 特徴

- **STL 内部のメッシュ**: solid 名ごとに壁パッチを作り、パッチ・特徴線・体積領域ごとに細分化レベルを指定できる
- **鋭角エッジの保持**: 凸・凹の特徴線に沿ってカット面を折り曲げ、節点をエッジ上へ寄せる
- **薄い形状への対処**: セルより薄い隙間・壁を検出して細分化し、流体の閉塞や壁の消失（リーク）を防ぐ。
  隙間の幅に合わせた自動細分化（`autoGapRefinement`）もある
- **境界層**: 壁パッチにプリズム層を追加（cutmesh 以外で作った ASCII polyMesh にも使える）
- **回転ゾーン（任意）**: 円筒（寸法または STL で指定）を**メッシュ生成の一部として**切断し、
  円筒面そのものを内部面にする。`cellZone`・向き付きの界面 `faceZone`・`MRFProperties` の雛形を出力する
- **円筒ベースメッシュ（任意）**: 回転機械向けに、八分木の根を軸まわりの同心ブロックにできる
- **依存が少ない**: Python 3.9+, numpy, scipy（断面図に matplotlib）。メッシュ生成に OpenFOAM は不要。
  幾何計算を Rust 拡張で高速化できる（任意）

> メッシュ品質は `checkMesh` と同じ式の自前チェック（`cutmesh/quality.py`）で確認していますが、
> OpenFOAM 本体での検証は限られています。使用前に手元で `checkMesh` を実行してください。

## インストール

```bash
pip install -e .                      # オフライン環境では --no-build-isolation（要 wheel）
python tools/build_rust.py            # 任意: Rust 拡張のビルド（下記「高速化」）
```

インストールしない場合はプロジェクト直下から実行するか、`PYTHONPATH` に `cutmesh` の親ディレクトリを通してください。

## 使い方

```bash
cutmesh meshDict.json [-case DIR] [-noCheck]    # python -m cutmesh でも同じ
```

最小限の `meshDict.json`（STL 内部だけのメッシュ）:

```json
{
  "domain": "model.stl",
  "baseCellSize": 0.01,
  "surfaceRefinement": { "default": 2 },
  "patchTypes": { "inlet": "patch", "outlet": "patch" },
  "case": "case"
}
```

`case/constant/polyMesh` が書き出され、続けて品質チェックの結果がログに出ます（`-noCheck` で省略）。

### 例題（攪拌槽）

`examples/stirred_tank` は、槽＋4枚パドル翼＋シャフトの形状に回転ゾーンを置いた例です。

```bash
cd examples/stirred_tank
python make_geometry.py               # サンプル STL を生成
cutmesh meshDict.json                 # → case/constant/polyMesh, case/constant/MRFProperties
python run.py                         # 断面図も欲しい場合 → slice_z.png, slice_y.png
```

| ファイル | 内容 |
|---|---|
| `meshDict.json` | 直交格子ベース、寸法指定の回転ゾーン |
| `meshDict_coarseRotor.json` | 回転ゾーン内部を粗くした例 |
| `meshDict_stlRotor.json` | 回転ゾーンを STL で指定 |
| `meshDict_cylindrical.json` | 円筒ベースメッシュ |
| `meshDict_layers.json` | 境界層（3層、全壁） |

`rotatingZones` を消せば、同じ形状で回転ゾーンのないメッシュになります。

## meshDict.json

| キー | 意味 | 既定値 |
|---|---|---|
| `domain` | 流体領域のSTL（閉曲面、複数solid可。solid名がパッチ名） | 必須 |
| `baseCellSize` | レベル0セルの辺長 [m] | 必須 |
| `surfaceRefinement` | solid名→細分化レベル。`default` で既定値 | `{}` |
| `featureLevel` | 特徴線近傍の細分化レベル（`null`=表面最大レベル） | `null` |
| `gapRefinement` | `{"thickness": t, "level": L}`: 流体の厚みが `t` 未満の所（スロットの鋭い先端、狭い流路）の壁を `L` まで細分化。セルより薄い部分が切り落とされるのを抑える | なし |
| `autoGapRefinement` | `{"cellsAcross": n, "maxLevel": L}`（`true` で既定値）: STL の各所で流体側の隙間の幅 w を測り（壁から法線方向に向かいの壁まで）、隙間に `n` 個のセルが入るレベル（`baseCellSize / 2^level ≤ w / n`、上限 `L`）まで壁を細分化する。溝・スリット・狭い隙間が閉じたりつぶれたりするのを、厚さを指定せずに防ぐ。その面の表面レベルですでに `n` 個入る所は対象外。上限でも足りない所の数をログに出す | なし（`n` = 3、`L` = 表面レベルの最大 + 2）|
| `featureAngle` | 特徴線抽出の角度 [deg] | 30 |
| `bufferLayers` | レベル遷移ごとのバッファセル数 | 2 |
| `snapTolerance` | 節点スナップ距離（セル辺長比）。スライバー防止 | 0.3 |
| `featureSnapTolerance` | 特徴線（STLの鋭角エッジ・円筒の縁）への節点スナップ距離（セル辺長比） | 0.5 |
| `featureSnapMax` | 実験的: この距離まで特徴線へスナップし、八分木セルが壊れる所だけ取り消す。現状は一部のカットセルが反転するため既定では無効（= `featureSnapTolerance`） | 0.5 |
| `concaveSnapMax` | 凹の鋭角エッジ（固体が流体側へ突き出した角）には、固体側にある節点をこの距離（セル辺長比）までエッジ上へ寄せる。隣のセルが壊れる・面の角が潰れる所は取り消す。`featureSnapMax` 以下で無効 | 0.75 |
| `featureGapSnap` | 格子に沿わない凸の鋭角エッジで、エッジ上の節点の間隔が 0.5 セルより空いている所ごとに、この距離（セル辺長比）以内の節点を 1 つエッジ上へ寄せる。カットはエッジ上の節点どうしを結ぶので、間隔が空くとその間が面取りされる。八分木セルが壊れる所は取り消す。結果はログの `feature gaps:` 行。エッジがかなり鋭くなるが（傾けた立方体で、エッジから 0.2 最小セル以上離れた部分が 16.5% → 5.1%）、境界層を付けると、そのエッジ（層にとっての入隅）で層が少し薄くなるため既定では無効 | 0（無効） |
| `mergeRatio` | 元hex体積比でこれ未満のカットセルを隣接セルに統合 | 0.25 |
| `mergeMaxNonOrtho` | 統合後の非直交角の上限 [deg]。満たす相手が無ければ統合しない | 65 |
| `hangingSnap` | 辺/面に沿って表面へ届かないぶら下がり節点の扱い（`"free"`=表面へ直接投影、`"constrained"`=動かさず φ=0 とみなす） | `"free"` |
| `fillThinGaps` | セルの中に流体があるのに角の頂点がどれも流体にない（格子の面の間を通る薄い隙間）セルを、最大レベルを1段超えて分割する回数。0 で無効。直交格子のベースのみ | 2 |
| `fillThinWalls` | 中に固体の薄い壁（セルを貫く線上で、表と裏の面がセル内にある）があるのに、角の頂点がどれも固体にないセルを分割する回数（1回ごとに最大レベルを1段超える）。壁が消えて両側の流体がつながる（バイパス）のを防ぐ。0 で無効。直交格子のベースのみ | 3 |
| `thinCutCells` | 壁で切られて流体が `thinCutFraction` 未満しか残らず、隣に細かいセルがあるセル（レベル遷移が壁にかかる所）を分割する回数。セル中心が壁に寄って細かいセルとの間の面の非直交性が大きくなるのを防ぎ、遷移を壁から離す。0 で無効。直交格子のベースのみ | 2 |
| `thinCutFraction` | `thinCutCells` の対象とする流体の割合（八分木セルの体積比、角の符号付き距離の補間で見積もる） | 0.35 |
| `checkLeaks` | 生成したメッシュで、流体が固体の壁を越えてつながっていないかを検査し、見つかれば警告と場所をログに出す | true |
| `strictInput` | STL に開いた辺・非多様体の辺があるとき、警告ではなくエラーで止める（下記「入力 STL の修正と検査」） | false |
| `volumeCheckTolerance` | 完成したメッシュの体積と STL の符号付き体積の差がこの割合を超えたら警告する | 0.05 |
| `minRegionVolume` | 流体の本体とつながっていない領域（鋭角の溝の先端がセルより細くなって切り離された断片など）のうち、体積が全体のこの割合未満のものを削除する。それ以上の領域は削除せず、警告を出す | 1e-3 |
| `refinementRegions` | 体積細分化領域 `[{"cylinder": {...}, "level": n}]` | `[]` |
| `featureCaps` | 凸の鋭角部でカット面を特徴線に沿わせる（`"domain"`/`"both"`/`false`。`"both"` は回転ゾーンにも適用） | `"domain"` |
| `patchTypes` | パッチ名→タイプ（`wall`,`patch`,…） | 全て `wall` |
| `rotatingZones` | 回転ゾーンのリスト（下記「回転ゾーン」）。省略時はゾーンなし | `[]` |
| `writeMRFProperties` | 回転ゾーンがあるとき `constant/MRFProperties` の雛形を書く | true |
| `case` | 出力先ケースディレクトリ | `.` |
| `addLayers` | 境界層の設定（下記「境界層」）。省略時は層なし | なし |
| `baseMesh` | ベースメッシュ（下記「円筒ベースメッシュ」）。省略時は直交格子 | 直交格子 |

## 回転ゾーン（`rotatingZones`、任意）

MRF やスライディングメッシュ（AMI）用の回転領域を円筒で指定します。円筒は八分木のカットで切断されるので、
円筒面そのものがメッシュの内部面になります（生成後にセル中心でゾーンを選ぶ方式ではありません）。

```json
{ "name": "rotor",
  "cylinder": { "point1": [0,0,0.06], "point2": [0,0,0.14], "radius": 0.07 },
  "surfaceLevel": 2, "volumeLevel": 2, "omega": 31.416, "nonRotatingPatches": [] }
```

- 出力: `cellZones`（回転領域）、`faceZones`（`<name>_interface`：円筒界面、向き付き）、
  `constant/MRFProperties` の雛形（`"writeMRFProperties": false` で書かない）
- 界面は粗いセルでも厳密に円筒面上にあるので、**界面のために細分化する必要がない**
  （snappyHexMesh で界面の faceZone を綺麗に取るための細分化に比べ、セル数を抑えられる）

STLで与える場合は `"cylinder"` の代わりに `"stl": "rotor.stl", "origin": [...], "axis": [...]`
（`examples/stirred_tank/meshDict_stlRotor.json`）。複数ゾーン可（重ならないこと）。

`"wallProximity": { "distance": 0.001, "level": 4 }`（任意）: ゾーン面のうちSTLから `distance` 以内の
部分だけを `level` まで細分化します。界面が壁から1セル未満しか離れていない（ローター外周すれすれに
MRF円筒を置く）場合、隙間より細かいセルが必要ですが、`surfaceLevel` を上げるとゾーン面全体が細かく
なってセル数が大きく増えます。`wallProximity` なら必要な所だけで済みます。
`"bufferLayers": 1` を加えると、この細分化の遷移層だけを薄くしてさらにセル数を減らせます。

`"conforming": false`（任意）: 界面をメッシュに沿わせず、セル中心が円筒内にあるセルを cellZone にします
（snappyHexMesh の MRF と同じ考え方。MRF は cellZone だけを使う）。界面が狭い隙間の中にあって円筒に沿った
界面を作れない場合に使います。AMI（スライディングメッシュ）には使えません。この界面は境界層の拘束面に
しません（層の追加後に cellZone から faceZone を作り直します）。

## 円筒ベースメッシュ（`cutmesh/cylbase.py`）

回転機械向けに、八分木の根を直交格子の代わりに軸まわりの同心ブロックにできます。

```json
"baseMesh": {
  "type": "cylindrical",
  "origin": [0, 0, 0], "axis": [0, 0, 1],
  "nz": 24,
  "core": { "halfWidth": 0.0375, "n": 6 },
  "blocks": [
    { "rOuter": 0.06, "nr": 2 },
    { "rOuter": 0.10, "nr": 3, "nTheta": 38 },
    { "rOuter": 0.155, "nr": 4 }
  ]
}
```

| キー | 意味 | 既定値 |
|---|---|---|
| `origin`, `axis` | 回転軸（原点と方向） | `[0,0,0]`, `[0,0,1]` |
| `zRange` | 軸方向の範囲 `[z0, z1]`（`origin` からの距離） | STL の範囲 ± `baseCellSize` |
| `nz` / `dz` | 軸方向の分割数 / 幅（全ブロック共通） | `dz = baseCellSize` |
| `core` | 中心の正方形ブロック: 半幅 `halfWidth`、一辺の分割数 `n` | 必須 |
| `blocks` | 外側へ並ぶ同心ブロック: 外半径 `rOuter`、半径方向の分割数 `nr`、周方向の分割数 `nTheta` | 必須 |
| `maxSizeRatio` | ブロック境界をまたぐセル寸法の比の上限（超える側を細分化） | 2.5 |

- 最初のブロックは正方形から円へつなぐ O グリッドで、`nTheta` は `4 × core.n` に固定。
- 2番目以降の `nTheta` は任意（隣のブロックの整数倍でなくてよい）。省略すると、平均半径で周方向の幅が
  半径方向の幅とほぼ同じになる値。
- ブロックの境界（正方形・円筒面）では、両側の面を重ね合わせて共有の面に分け、辺上の頂点を周りの面に
  入れるので、分割数の比が任意でも適合した多面体メッシュになる（AMI 不要）。
- 表面・特徴線・ゾーン・領域による細分化はそのまま使える。ブロックのセルは寸法がそろっていないので、
  レベル L は目標寸法 `baseCellSize / 2^L` として扱い、最長の辺が目標の 1.3 倍以下になるまで分割する。
  細長いベースセルは短い辺の方向まで細かくなるので、各ブロックのセルが立方体に近くなるように分割数を選ぶ。
- 最外ブロックの `rOuter` は STL の半径より大きくする（小さいと警告。STL は切り取られる）。
- 例: `examples/stirred_tank/meshDict_cylindrical.json`（13.7万セル、非直交角 max 63°、面ピラミッドの負 0）。

## 境界層（`cutmesh/layers.py`）

壁パッチにプリズム層を追加します。メッシュ生成とは独立した後処理で、polyMesh を入力にします。

```bash
# meshDict.json に "addLayers": {...} を書くと生成後に自動で追加
python -m cutmesh meshDict.json
# 例: examples/stirred_tank/meshDict_layers.json（3層、全壁）→ case_layers（約16万セル、壁節点の98%が目標厚さ）
cutmesh examples/stirred_tank/meshDict_layers.json
# 既存ケースに追加（ASCII polyMesh。cutmesh 以外のメッシュでも可）
python -m cutmesh.layers CASE [layerDict.json] [-out CASE2] [-noCheck]
```

| キー | 意味 | 既定値 |
|---|---|---|
| `patches` | 層を付けるパッチ名のリスト | type が `wall` の全パッチ |
| `nLayers` | 層数 | 3 |
| `expansionRatio` | 壁から内側への層厚の比 | 1.2 |
| `finalLayerThickness` | 最も内側の層の厚さ（`relativeSizes` なら局所セル寸法比） | 0.3 |
| `relativeSizes` | 厚さを局所セル寸法（壁セルの最大寸法）に対する比で与える | true |
| `minThickness` | 総厚がこれ未満の所は層を付けない | 0.05 |
| `minNormalCos` | 節点法線と面法線の cos がこれ未満（鋭い凸エッジ）の所は層を付けない | 0.25 |
| `maxNonOrtho` | 非直交角 [deg] がこれを超えるセルは不正とみなす（元からある内部面は元の値 + 2° まで許す） | 65 |
| `maxSkewness` | skewness（checkMesh と同じ定義）がこれを超える面のセルは不正とみなす（元からある面は元の値 + 0.2 まで許す。`null` で無効） | 4 |
| `wallNonOrthMargin` | 元の壁面（層の挿入後は内部面）に、境界面としての角度 + この値 [deg] まで許す。被覆率は上がるが 70° 超の面が出る | なし |
| `maxThicknessSlope` | 壁に沿った単位長さあたりの総厚の変化の上限（層の端を徐々に細らせる） | 0.5 |
| `cornerStretch` | 角の節点を T/cos 動かし、角でも層厚 T を保つ | true |
| `maxGapFraction` | 総厚を、向かい合う壁までの距離のこの割合以下に抑える（狭い隙間で両側の層がぶつからないように。0 で無効） | 0.3 |
| `mergeWallPoints` | 層を付ける前に、壁上でこの値 × 周りの壁の辺長より近い節点どうしを1点にまとめる（0 で無効） | 0.1 |
| `concaveSlide` | 凹の角で、もう一方の壁の層に食い込む節点を自分の壁に沿って滑らせる。元の距離 s0 の所にある節点を、もう一方の壁の層厚 c に対して c + k·s0 まで離す（k がこの値。`null` で無効） | 0.5 |
| `nRings` / `nSmooth` | 内部節点を押し込む範囲（壁からの辺数）とラプラス平滑化の回数 | 6 / 60 |
| `nIter` / `nCollapseIter` | 不正セルの所の厚さを半減する反復回数 / その後に層を止める反復回数 | 8 / 60 |

`"addLayers": {}` は既定値で層を追加します。狭い隙間（壁間が壁セル寸法程度）がある形状では、既定の
`finalLayerThickness` 0.3（総厚は壁セルの約0.76倍）だと層が薄められがちです。0.15（約0.38倍）程度にすると
目標厚さに達する節点が大きく増えます。

手順:
0. 凹のエッジ沿いには、カットでほぼ重なった壁節点（エッジ上へスナップした八分木の頂点と、そのすぐ横のカット点。
   間隔はセルの数千分の1〜数百分の1）が残ることがある。その間の長さほぼ0の辺は向きが定まらず、その上の層の
   側面や、エッジに沿った細い壁面が層を付けると裏返り、エッジに沿って層が止まる。そこで、`mergeWallPoints` ×
   周りの壁の辺長より近い壁節点を、壁面の多い方（角の節点）にまとめる。点が3つ未満になる面（まとめた後は面積0）
   は除く。他のパッチや faceZone 上の節点はまとめない。まとめると面が自分自身に触れる、セルの面が4つ未満になる、
   セルが不正になる（体積が正でない・元の半分未満、面ピラミッドが正でない。壁上の短い辺だけからなる薄いセルは
   つぶれる）節点の組はまとめずに残し、残りの組だけで確かめ直す。
1. 壁節点を面積重み付き節点法線に沿って内側へ総厚 T だけ動かす。複数の平面にまたがる節点（エッジ・角）は、
   面積ではなく各平面から T 離れる位置（オフセット面の角。2平面なら二等分線上で T/cos(θ/2)）へ動かす
   （面積重み付きでは大きい面に引っ張られ、一方の壁から離れすぎ、もう一方からは足りなくなる）。
   凹の角の近くでは、一方の壁の節点がそのまま法線方向に動くと、二等分線上を動く角の節点より奥に入り、
   間の層のセルが裏返る。そこで、もう一方の壁の面（の平面）から c + k·s0（c: その面の層厚、s0: 元の距離、
   k = `concaveSlide`）より近い節点は、自分の壁に沿ってその面から離れる方向へ滑らせる。k < 1 なので
   角から c/(1−k) 以内の節点は順序を保ったまま扇状に詰められる。内部節点は、壁から `nRings` 辺以内を
   ラプラス平滑化（辺長の逆数で重み付け）で追従させる。辺でつながる節点だけに伝わるので薄い固体を
   越えず、壁際の薄いカットセルはほぼ剛体的に動く。
2. 層を付けないパッチ（inlet/outlet など）と faceZone（回転ゾーン界面）上の節点は、その面に沿ってのみ
   動かす。壁節点のうちそれらの縁にあるものも押し込み方向を面内に射影する。界面は円筒のまま保たれ、
   層の側面のうち界面上にあるものは faceZone に加わる。
3. 元の壁位置と押し込んだ位置の間に、壁面ごとに `nLayers` 個のプリズムを挿入する。元の壁面は
   最初の元セルとの内部面になる。
4. 体積・面ピラミッド・非直交角で不正なセルがあれば、関わる壁節点の厚さを半減し、それでも残れば
   0 にする（その節点で層の点が1点に縮退し、層はくさび形のセルで終わる。snappyHexMesh と同じ）。
   厚さは壁に沿って `maxThicknessSlope` で滑らかに変化させる。

ログに、目標の厚さに達した壁節点・薄くなった節点・層なしの節点の割合が出ます。

被覆率を制限しているのは主に、カットセルの重心が壁面の法線上からずれていることです（壁面の法線と
「面中心 − セル重心」のなす角。元のメッシュでは境界面なので checkMesh の対象外）。層を挿入すると
その面が内部面になり、角度がほぼそのまま非直交角になるため、`maxNonOrtho` を超える所で層が止まります。

## 高速化（Rust 拡張、任意）

最近点・内外判定・符号付き距離（STL と特徴線）、特徴線が面を貫く点（鋭角エッジに沿わせるカット）、フックなしのカット（回転ゾーン）、面・セルの重心と体積（品質チェック、セル統合、
境界層の判定で使う）、境界層の内部節点の平滑化とセルの妥当性検査を Rust（`rust/`、BVH + rayon による並列化）で計算します。Rust ツールチェーン（cargo）があれば次でビルドされ、`cutmesh/_core.pyd`（Linux/macOS は
`.so`）が置かれます。無ければ従来の Python/NumPy の処理で動きます（結果は同じ）。

```bash
python tools/build_rust.py            # cargo build --release + パッケージへコピー
CUTMESH_NO_RUST=1 python -m cutmesh meshDict.json   # Python の処理を強制（比較用）
python -m unittest discover -s tests  # Rust と Python の結果の一致を確認
```

|---|---|---|
| examples/stirred_tank | 26 s | 7 s |
| 別の実形状（55万セル） | 162 s | 41 s（節点スナップ 44→2 s、STL のカット 59→8 s、回転ゾーンのカット 10→1 s、セル統合 29→9 s） |
| 同、境界層の追加（3層） | 51 s | 27 s |

## アルゴリズム

1. **八分木**: 根グリッド → 表面・特徴線・円筒面・円筒内部の距離基準で細分化 →
   26近傍2:1バランス。ぶら下がり節点は多角形面の頂点として取り込み、面単位で完全適合。
2. **レベルセット**: STLは光線パリティで内外、近傍のみ厳密最近点距離。円筒は解析式。
3. **節点スナップ**: 特徴点・特徴線（`featureSnapTolerance×h` 以内）→ 面（`snapTolerance×h` 以内）の順に節点を移動。
   面上の節点は φ=0 として扱うためスライバーセルが出ない。ぶら下がり節点はまず粗い側の面を
   平面に保つよう辺/面に沿って移動し、届かない（辺/面が表面とほぼ平行な）場合は通常の節点と同じく
   表面へ直接投影する（`hangingSnap: "free"`。粗い側の面がわずかに反る）。投影で八分木セルが壊れる
   所だけ取り消す。`"constrained"` では従来通り動かさず φ=0 とみなす（壁に ≤ 0.3h のくぼみが残る）。
4. **カットセル**（`cutcell.py`）: 多面体を頂点のφで切断。面の分割は**その面の頂点値だけ**
   で決め、交点は辺キーで共有するので隣接セル間で必ず一致（適合性が構成的に保証）。
   カット面＝負側面集合の開いた境界を閉じるループ。
   - 1回目: STLで切断し内側のみ残す → カット面が壁パッチになる
   - 2回目以降（回転ゾーンがある場合）: ゾーンの円筒で切断し両側を残す → カット面が**界面の内部面**になる
   - 交点は面へ投影。STLと円筒の交線上の点（シャフト貫通部など）は交互射影で交線へ。
   - **鋭角エッジの保持**（`featureCaps`）: 特徴線がセル面を貫く点を、その面のカット線（弦）に
     挿入する（面キーでキャッシュするので隣接セルと一致）。セル内のカット面は、入口・出口の
     特徴点を結ぶ特徴線（曲線は中点の再帰投影で追従、角点ではスポーク分割）に沿って折り曲げる。
     折り曲げで非凸になったセルは、その面を共有するセルごと従来の面取りカットにやり直す。
     このため凸のエッジは捉えられるが、凹のエッジと円筒縁の外側（常に凹）は面取りのまま。
   - **凹エッジ際の壁接触**（STLのみ）: 凹エッジ（穴の縁や段差の入隅）の隣では、壁面上の節点（φ=0）が
     連なって面に乗る。φ=0 を一律に流体側として補間するとエッジが格子位置次第で 0〜h 面取りされ、
     エッジに沿って凸凹になるため、(a) N と P に挟まれた φ=0 の連続では、φ=0 どうしの辺の内側の点で
     固体／流体を判定し、固体に入る節点でカット線を切る（面単位の判定なので隣接セルと一致。
     表面に届かなかったぶら下がり節点を含む辺は対象外）、(b) 全節点が壁上にある面は、セル側が固体の
     セルからは外す（流体側のセルの壁面になる）、(c) 流体側の節点と、壁上の節点（3つ以上連続）を
     持つ面（穴の縁で縁の外の平面にかかる面など）は、壁上の節点の連続の両端を結ぶ弦で流体部と
     接触部に分け、接触部は固体側のセルから外す（流体側のセルの壁面になる。カットされないセルも
     分割した面を持つ断片になる）。接触部が細い（幅 < 0.1h）ときは分けない。いずれも既存の節点だけを使う。
5. **小セル・非凸セル統合**: 体積比 `mergeRatio` 未満のカット断片と、自分の重心が見えない面を持つ
   （非凸の）セルを、同一ゾーン内の隣接セルへ統合。候補ごとに統合後の形状を評価し、全面の
   ピラミッド体積が正で、隣接セルとの非直交角が最も小さい相手を選ぶ（`mergeMaxNonOrtho` 超は不採用）。
   統合できずに残った小セルのうち、面の三角形分割の四面体が負になる壁際の薄片（曲面の壁と壁上に
   乗った面に挟まれたレンズ状のセルなど）は削除し、その面を隣接セルの壁面にする（面ピラミッドが
   負のものは常に、四面体だけが負のものは露出する面が STL から 0.4h 以内の場合のみ）。
6. **出力**: 上三角順の内部面、パッチごとの境界面、cellZone/faceZone、未使用点の除去。
   1つのセルの壁面が辺を共有する複数の面に分かれている所（統合した小セルの壁面など）は1つの面にまとめる。
   曲面の壁（円錐など）では断片がわずかに折れ曲がっているので、隣どうしの法線が 5° 以内で、まとめた面の
   法線から各断片が 2.5° 以内ならまとめる（折れが 5° までの2枚はまとまり、曲がり続ける帯はまとめない）。
   別々のままだと小さい断片の面中心がセル中心の法線上から大きく外れ、境界層を挿入するとその面の
   非直交角が `maxNonOrtho` を超えて層が止まり、それが隣へ次々に伝わって壁に沿った帯状に層が欠ける。

## 診断ツール

`python tools/edge_check.py <meshDict.json> [-case DIR]` は、STLの特徴線と円筒ゾーンの縁に沿って
点を取り、最寄りのメッシュ辺（境界面・界面faceZone）までの距離を最小セル寸法比で表示します。
エッジが捉えられていれば0、面取りされていればセル寸法の数割になります。

`python -m cutmesh.diagnose meshDict.json [CASE]` は、既存のメッシュで流体が固体の壁を越えてつながっていないか
（`checkLeaks` と同じ検査）を調べます。

## 入力 STL の修正と検査

**仕様: cutmesh が入力を自動で修正したときは、必ずログに `REPAIR:` で始まる行を出し、何を何件直したかを記録する。**
黙って直すことはしない（`cutmesh.diagnose` や `tools/edge_check.py` が STL を読むときも同じ行を出す）。

読み込み時に自動で直すもの（`geometry.repair_triangles`）:

| 修正 | 理由 |
|---|---|
| 面積 0 の三角形を除く | 法線が決まらず、特徴線や交点の計算を乱す |
| 重複した三角形（同じ 3 頂点・同じ向き）は 1 枚だけ残す | 内外判定（光線の交差回数の偶奇）で交差が 2 回数えられ、光線の方向に内外が反転する |
| 重なった逆向きの三角形の対（厚さ 0 の膜）は 2 枚とも除く | 同上。流体の中の膜は内外判定に寄与しない |

```
REPAIR: domain STL: removed 20 zero-area triangles, 50 duplicated triangles (one copy kept) (1350 -> 1280 triangles)
```

直さずに検査して `WARNING:` を出すもの（場所の例つき）: 開いた辺（閉じていない）、非多様体の辺（3 枚以上の
三角形が共有）、隣り合う三角形で向きが食い違う辺。`"strictInput": true` なら、開いた辺・非多様体の辺で
エラーにして止める。問題がなければ `domain STL check: closed, consistently oriented, N triangles` と出る。

メッシュの完成後には、メッシュの体積を STL の符号付き体積と比べる（`volume check: mesh ..., STL ... (+x%)`）。
`volumeCheckTolerance`（既定 5%）を超えると警告する。STL が開いている・自己交差している（光線の偶奇で
内外を取り違える）、またはセルより細い流体が切り落とされた可能性がある。向きが揃っていない STL では省略する。

## 既知の制約

- STLは水密（閉じた・向きの揃った）である必要あり。面積 0 や重複した三角形は読み込み時に除くが（ログに `REPAIR:`）、開いた辺・自己交差は直さない（開いた辺は警告、自己交差は体積チェックの警告で分かることが多い）
- セルより薄い形状（薄翼・バッフル板）は、その厚さ程度まで細分化が必要
- セルより薄い流体の隙間は、閉じないように扱う: 格子の面の間を通る隙間は `fillThinGaps` で細分化し、頂点の面が中を通る隙間では、スナップで壁に寄せるとセルが流体の頂点を失う場合に、その頂点を隙間の中央へ動かす（壁に近すぎて中央へ動かせない頂点は従来どおりスナップ）。円筒ベースでは `fillThinGaps` は未対応
- セルより薄い固体の壁は、消えないように扱う（消えると両側の流体がつながり、計算が破綻する）: 角の頂点が壁に入らないセルは `fillThinWalls` で細分化し、固体側の頂点がスナップで両面に寄せられてセルが固体の頂点を失う場合は、その頂点を壁の厚みの中央へ動かす。それでも残るつながりは `checkLeaks` の警告で分かる（`python -m cutmesh.diagnose meshDict.json [CASE]` で既存のメッシュも検査できる）。壁と別の壁が交わる入隅では、面取りが残ることがある
- 格子に沿わない凸の鋭角エッジは、エッジ上の節点の間隔が空いた所で面取りされる（`featureGapSnap` で大きく減らせるが、境界層を付けるとそのエッジで層が少し薄くなるので既定では無効）
- 円筒の縁（リム）や凹の鋭角部はセル寸法程度で面取りされる（界面としては実用上問題小）。
  凸の鋭角部は `featureCaps` と特徴線スナップで多くが捉えられる。凹の鋭角部は、固体側の節点を
  `concaveSnapMax×h` までエッジ上へ寄せて捉える。近くに固体側の節点がない所（レベル遷移とエッジが
  重なる所など）では、壁上の節点を壁に沿ってエッジ上へ滑らせ、エッジ上の節点と壁の節点が囲む固体の
  楔をセルから除く。角が粗いセルの面（ぶら下がり節点）に当たる所は、面の切断線をその節点で折り曲げ、
  セルをエッジに沿って2つに分ける。どの節点もエッジに届かない所（角がセルの中央付近にあり、周りの
  壁の節点がぶら下がり節点かその親の所）は面取りが残る
- skew>4 の境界面が少数残る（checkMeshでは "highly skew faces" として1項目失敗扱いになる可能性あり）
- レベル遷移が壁にかかる所のぶら下がり節点は表面へ投影するので壁の凹凸は出ないが、投影で
  八分木セルが壊れる所は取り消され、そこだけ最大0.3×最小セル程度のくぼみが残る
- 統合相手が見つからない小セルはそのまま残る（最小体積が小さくなる）
- 幾何問い合わせ以外（カット、セル統合、組み立て）は Python のままで、残りの時間の大半を占める

## ロードマップ

1. **境界層**: 自前実装の初版あり（上記）。今後: 層の被覆率の向上（狭い隙間や鋭いエッジでの
   厚さの割り当て）、法線の平滑化、層の品質指標（アスペクト比など）の出力
2. **品質改善**: レベル遷移とカットが重なるセルの追加細分化、薄い（扁平）セルの統合基準
3. **Rust 化**: 距離計算（BVH）は Rust 拡張に移行済み（上記「高速化」）。次はカット（セル単位で
   独立なので並列化しやすい。交点を辺ごとに一括で求めてからセルごとに切る構造にする）、セル統合
4. **AMI（スライディングメッシュ）**: 回転ゾーンの `<name>_interface` faceZone を `createBaffles` で
   切り離し、cyclicAMI にする（手順は snappyHexMesh のチュートリアルと同じ）
